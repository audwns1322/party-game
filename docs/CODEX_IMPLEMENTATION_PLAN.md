# Codex 전달용 개발 작업 계획서 v1.0

> 선행 문서: `PRD_FINAL_v1.0.md` — PRD를 단일 진실원(Single Source of Truth)으로 사용  
> 목표: 라이어 게임 1종을 모바일 실시간 멀티플레이로 안전하게 출시  
> 권장 작업 방식: **한 단계씩 코드 변경 → 테스트 → 검토 → 다음 단계**. 전체 기능 일괄 생성 금지.

## 1. 작업 원칙

1. React + TypeScript + Vite / Supabase(Postgres, Edge Functions, Realtime) / Vercel 고정.
2. 처음에 기존 Git repo가 있는지 확인하고, 있으면 기존 코드를 보존하며 분석한다. 신규 프로젝트일 때만 스캐폴딩한다.
3. 시작 전에 요구 환경변수 목록과 설정 방법을 `README.md`, `.env.example`로 문서화. 실제 비밀을 출력·커밋하지 않는다.
4. DB 마이그레이션 SQL, 서버 함수, UI, 자동 테스트를 한 번에 대량 생성하지 말고 작은 PR/커밋 단위로 작성.
5. 화면만 연결해서 성공으로 간주하지 않는다. **서버 검증, 역할/단어/투표 비밀 보호, 중복 요청 통제**가 필수.
6. Supabase 기능이나 가격·쿼터가 불명확할 때는 공식 문서를 확인하고 선택 이유를 기록.
7. 각 단계 종료 시 `완료 항목 / 테스트 결과 / 미완료·위험 / 다음 단계`를 보고한다.

## 2. 추천 저장소 구조

```text
/
├── src/
│   ├── app/                 # 라우트, 공통 앱 진입점
│   ├── components/          # 재사용 UI
│   ├── features/
│   │   ├── room/            # 생성·입장·대기실·재접속
│   │   └── liar/            # 라이어 전용 화면·클라이언트 DTO
│   ├── lib/                 # API 클라이언트·세션·실시간
│   └── styles/
├── supabase/
│   ├── migrations/          # 버전 관리 SQL
│   ├── functions/           # 권한 검증/명령/개인 스냅샷
│   └── seed.sql             # 안전한 기본 제시어
├── tests/
│   ├── unit/
│   ├── integration/
│   └── e2e/
├── docs/
│   ├── PRD_FINAL_v1.0.md
│   ├── CODEX_IMPLEMENTATION_PLAN.md
│   ├── DECISIONS.md
│   └── TEST_MATRIX.md
├── .env.example
└── README.md
```

파일 구조는 실제 SDK와 도구에 맞춰 최소 변경 가능. 무의미한 범용 게임 추상화는 구현하지 않는다.

## 5. 완료 정의(모든 마일스톤 공통)

- TypeScript 타입 검사/빌드 성공, 관련 단위·통합 테스트 통과.
- SQL 마이그레이션 업·다운 또는 되돌리기 안내 및 초기 DB에서 재현 가능.
- 사용자 입력 검증 및 서버 측 접근 권한 확인.
- 코드에 실제 비밀 키, 개인정보 또는 투표 원문을 로그 출력하지 않음.
- UI 오류 시 사용자에게 재시도/복귀 경로 제공.
- 변경 결정은 `docs/DECISIONS.md`에 기록.
- 다음 단계 시작 전 사용자에게 테스트 결과 및 잔여 위험 보고.

## 6. Codex 첫 요청 — 그대로 복사해서 사용

```text
이 저장소의 docs/PRD_FINAL_v1.0.md와 docs/CODEX_IMPLEMENTATION_PLAN.md를 먼저 읽어줘.
목표는 같은 장소에서 각자의 스마트폰으로 진행하는 라이어 게임 웹앱 MVP야.
기술 스택은 React + TypeScript + Vite + Supabase + Vercel로 고정한다.

먼저 M0(환경·보안 아키텍처 검증)만 수행해줘. 기존 프로젝트가 있다면 보존하고 분석해.
익명 참가자 토큰/Edge Function 권한 검증/비밀 테이블 보호에 대한 최소 POC를 우선 구현하고 테스트해.

M0 완료 후에는 변경 파일 목록, 실행 방법, 테스트 결과, 잠재 위험, M1 진행 전 필요한 설정만 보고해.

```
