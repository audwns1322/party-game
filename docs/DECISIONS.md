# 설계 검토 및 결정 — M0

## M2 — 2026-10-24

- 사용자 지시에 따라 M2만 진행. 모바일 3대 M1 인수 확인과 대기실 안내 문구 최종 재검토는 보류하고, 나중에 필요한 것을 물으면 다시 안내한다.
- 최신 M1 `13d478c`에서 작업. 이전 로컬 M0 변경은 `codex-m0-local-preserved-before-m2-20261024` stash에 보존했으며 자동 병합하지 않았다.
- 단계는 LOBBY → COLLECT_WORDS(직접 입력) → REVEAL_ROLE → HINT까지. 배정은 트랜잭션 내부에서 완료한다. 힌트 진행/토론/투표는 구현하지 않는다.
- 별도 game-command로 기존 M1 명령 재시도와 게임 명령을 구분한다. 방 version + expected_phase + round_id + request_id를 검증하고 room 행 잠금을 공유한다. 동일 요청은 같은 공개 결과를 재생하되 재방송하지 않는다. 중복 키의 내용 변경은 거부한다.
- 라이어 선정과 공개 발언 순서를 독립적으로 무작위 선정. 역할/후보/단어는 private 스키마, owner DTO만 반환한다. 직접 입력 중에는 본인 역할도 미공개이며 라이어 후보는 선정에서 제외한다.
- 중간 입장자는 다음 판 대기, 역할/제출/확인 명령 권한 없음. 미완성 단계에서 안전하게 재검증하도록 방장에게 점수 없는 판 취소를 제공한다. 판 참가자의 퇴장·강퇴·설정 변경은 먼저 취소한 후 가능하고 대기자 퇴장은 허용한다. 실제 단절 자동 정지/재개는 M6에서 구현한다.
- 기존 `/room/:code` 안에 역할 패널을 추가해 같은 useRoom 구독을 유지한다. 개인 역할은 누르는 동안에만 DOM에 렌더링하고 blur/visibilitychange에도 숨긴다. 네트워크 지연으로 낮은 version 응답이 덮어쓰는 것을 방지한다.
- 개발 DB migration 버전은 MCP 반환값에 맞춰 파일명 정합화했다: 20261024130245, 20261024130708. 기존 데이터와 M1 이력은 유지했다. FK 인덱스 누락은 후속 migration으로 보완했다.
- 실제 개발 Edge/DB/서버 Broadcast 검증과 UI smoke를 수행했다. 공개 frontend main은 병합하지 않고 초안 PR로 검토한다. 보안 스캔은 기본 거부 private RLS INFO만 남았다. 자세한 결과와 rollback 절차는 [M2_VALIDATION.md](M2_VALIDATION.md).

첨부 ZIP에는 PRD와 계획서 2개만 있었으며 모두 읽고 원문을 docs에 보존했다. 문서의 예시·후속 단계 지침은 참고 요구사항으로 다루고, 사용자가 요청한 M0만 구현한다. 기존 저장소는 README 1개, 초기 커밋 b155207, 작업 트리 깨끗함. 체크아웃 브랜치는 플랫폼이 제공한 `work`다. 원격 main을 변경하거나 push하지 않았다.

## 정합성

1. **명백한 오기:** PRD §2.4 마지막의 “시민이 아닌 사람을 지목했다면 라이어 즉시 승리”는 §2, §4의 “라이어 지목 시 GUESS”와 모순이다. 상세 상태 머신을 기준으로 시민 지목 시 라이어 승리, 라이어 지목 시 정답 도전으로 해석한다. M0에는 승패 로직을 구현하지 않는다. M1 진행 확인 시 함께 검토 가능하다.
2. **토큰과 JWT는 다름:** PRD의 자체 무작위 토큰은 Supabase Auth JWT가 아니다. 해당 Edge Function만 `verify_jwt=false`로 설정하고, 함수 내부에서 Bearer 토큰 형식 → SHA-256 해시 → 방/활성 자격 조회를 반드시 수행한다. 공용 API 키를 참가자 인증으로 사용하지 않는다. 새 함수는 기본 JWT 검증 상태를 별도로 검토한다.
3. **RLS만으로 충분하지 않음:** service_role은 RLS를 우회한다. 비밀 테이블은 노출되지 않는 `m0_private` 스키마에 두고 anon/authenticated의 스키마·테이블·RPC 권한을 회수한다. Edge는 고정 RPC만 호출하고, RPC가 해시+방+활성 여부를 검증한다. SECURITY DEFINER에는 빈 search_path와 완전 수식 테이블명을 사용한다. 운영에서는 전용 최소 권한 DB 실행 역할도 검토한다.
4. **공개 Realtime의 신뢰 경계:** public 채널은 악의적 참가자의 위조 이벤트를 배제하지 못한다. 공개 payload는 `{room_id, version}`만 허용하고, 상태 결정·역할 확인·Presence의 진위 판단에 사용하지 않는다. 이벤트는 인증된 HTTP 재조회 힌트일 뿐이다. 운영의 서버 송신 전용 권한/쿼터·재조회 병합·재연결 폴링은 M2/M6에서 검증한다. 비밀은 절대로 Broadcast하지 않는다.
5. **연결 판정/타이머:** 공개 Presence를 참가자 권위 증명으로 쓰지 않는다. 향후 인증 heartbeat와 서버 시간·DB 트랜잭션이 최종 권위다. Edge 함수 실행을 2시간 유지하거나 JS setTimeout을 운영 스케줄러로 사용하지 않는다.
6. **M0/M1 경계:** 보안 POC는 m0_private.sessions 한 테이블만 사용한다. 방·회복 코드 발급·회전 API·게임·승점은 아직 구현하지 않았다. 테스트의 SQL 자격 교체는 폐기 자격 차단만 증명한다. M1부터 운영 모델을 별도 마이그레이션으로 작성하고 POC는 운영 배포 전 제거한다.
7. **M0 완료 조건:** 단위 테스트만으로 보안 완료를 주장하지 않는다. 실제 로컬 Postgres 권한 테스트, Edge HTTP 호출, Realtime 송수신까지 통과해야 한다. 원격 Supabase/Vercel과 실기기 QA는 별도 미검증이다.

## 현재 런타임 차단과 대체 검증

Docker daemon의 storage driver가 vfs이며 전체 디스크 32GB다. 공식 Postgres 17.11 이미지(검증된 레지스트리 manifest 기준 29개 레이어, 압축 약 351MB)를 해제할 때 누적 복제로 디스크가 가득 찼다. 설치 프로세스를 중단하자 미완료 레이어가 해제되어 여유 공간 약 21GB로 복구됐다. 서비스는 시작되지 않았고 실행 중 컨테이너는 없다. 다른 작업의 파일/컨테이너를 삭제하지 않았다. DB major 15의 최신 이미지도 유사한 레이어 규모라 근거 없는 다운그레이드는 하지 않는다.

PGlite(임베디드 실제 PostgreSQL/WASM)에 같은 마이그레이션을 적용해 GRANT/REVOKE, RLS 활성화, 실제 서버 핸들러→SQL RPC의 본인 정보/라이어 단어 차단, 자격 교체/폐기 테스트를 추가했다. 이 테스트는 Supabase gateway, Edge 런타임 HTTP, Realtime WebSocket을 검증하지 않는다. 해당 통합은 미완료로 남긴다. Deno CLI로 실제 Edge 진입점 타입 검사도 별도 수행한다.

# 설계 결정 — M1 (2026-10-24)

1. **비공개 스키마 + service_role 전용 RPC:** `app_private.rooms/players`는 PostgREST 비노출, anon/authenticated 권한 회수, RLS 활성(정책 없음 = 전면 거부). Edge만 `public.room_*` RPC를 호출하고 RPC가 토큰 해시·방·상태를 직접 재검증한다. SECURITY DEFINER + 빈 search_path.
2. **불변식은 DB에서:** 방장 ∈ 같은 방 참가자(복합 FK, deferrable), 열린 방끼리 코드 고유(부분 unique), 방 내 활성 닉네임 대소문자 무시 고유, 12명 상한은 방 행 잠금 후 검사.
3. **세션/복구:** 토큰 256비트 hex, 복구 코드 128비트(Crockford base32 26자, 4자 묶음). DB에는 SHA-256 해시만. 복구 성공 시 **토큰과 복구 코드 둘 다 회전** → 기존 기기 즉시 403. 복구 코드는 앱에 저장하지 않고 발급 직후 1회만 표시.
4. **버전과 동기화:** 상태 변경마다 `rooms.version` 증가. Realtime은 `{room_id, version}` 힌트만(REST broadcast, 실패해도 명령 성공). 클라이언트는 10초 heartbeat 응답의 version으로도 변경을 감지해 스냅샷을 재조회한다 → Realtime이 끊겨도 동작.
5. **heartbeat는 활동 아님:** 연결 표시(30초)만 갱신하고 2시간 만료 시계는 늘리지 않는다. 만료된 방은 모든 RPC에서 닫힌 방으로 취급(정리 스케줄러는 M6).
6. **대기실 명령 충돌 재시도:** 참가자 입장도 version을 올리므로 방장 설정 변경이 자주 409가 된다. `update_settings/leave/close_room`만 클라이언트가 최신 version으로 **1회 재시도**. M2 이후 게임 명령에는 적용하지 않는다(오래된 의도는 실제 충돌).
7. **방장 이탈:** 명시적 `leave`는 즉시 입장 순서상 다음 참가자에게 위임, 남은 사람이 없으면 방 종료. 연결 끊김에 의한 30초 지연 위임은 M6.
8. **보류:** `command_receipts` 멱등 처리(request_id는 이미 필수), API 속도 제한·방 코드 브루트포스 방어(M6/M7), 중간 입장자 `waiting_next_round`(M2).
9. **마이그레이션 파일명 = 원격 적용 버전**(`20261021071859`, `20261024064956`)으로 맞춰 CLI 이력 불일치를 방지한다.

# 설계 결정 — M1 보강 (2026-10-24, 전문가 3인 테스트 반영)

1. **닉네임:** NFKC 표시명 + 혼동 문자 접기 키(`nickname_key`, Edge에서 계산)로 방 내 고유성 판단. 보이지 않는/채움/양방향 문자·고립 서로게이트·라틴+키릴/그리스 혼합 거부. ZWJ는 이모지 결합에서만 허용. 길이는 화면 글자(grapheme) 2~16.
2. **방장 관리:** `kick`(내보낸 토큰 즉시 403), `lock`(새 참가 `ROOM_LOCKED`). 방당 누적 좌석 50 상한(입퇴장 반복으로 행 증가 방지).
3. **속도 제한:** `rate_hit` 고정 창 카운터, IP는 해시로만 저장. 10분당 생성 10/IP, 참가 30/IP·60/방, 복구 10/IP·30/방 → 429 `RATE_LIMITED`. 정상 모임 규모 대비 여유 있게 설정.
4. **명령 처리:** 토큰 확인 후 방 잠금(무작위 토큰으로 잠금 경합 불가), 잠금 후 재확인. 변경 없는 설정/잠금·복구는 version·broadcast 없음. expected_version 1~2^31-1만 허용, heartbeat는 무시.
5. **복구 코드 표시:** 참가 직후 모달 대신 대기실 "다른 기기로 옮기기"에서 필요할 때 표시. 이를 위해 이 기기 저장소에 토큰과 함께 보관(같은 저장소에 이미 토큰이 있어 위험 증가 없음). M1 결정 3의 "앱에 저장하지 않음"을 대체.
6. **UX:** 처음 화면 "참가 중인 방으로 돌아가기", 같은 방 재참가 시 기존 자리로, 연결 끊김 배너·재시도, 참가/퇴장/방장 변경 안내, native confirm 대신 2단계 버튼, 주요 버튼 대비 5.5:1.

# 설계 결정 — M3 (2026-10-24)

1. **서버 cursor:** M2의 고정 참가자/순서를 재사용한다. 완료 횟수 `hint_index`로 발언자와 바퀴 수를 계산하고 방 잠금·version/phase/cursor 검사로 중복·이전 차례를 거부한다.
2. **요청 시 만료 검증:** PRD의 요청 시 검증 방식을 선택. DB `deadline_at`과 서버 시간으로 인증 snapshot/heartbeat 안에서 DISCUSS→VOTE_1을 한 번 반영한다. 상주 타이머 프로세스/새 스케줄러는 추가하지 않는다. 무접속 시 다음 요청에서 확정한다.
3. **화면과 동기화:** 서버 시각과 기한으로 카운트다운을 표시한다. 표시는 전환 권한이 없으며, 토론 중 2초 snapshot과 기존 heartbeat/Realtime으로 최신 상태를 받는다. 전환 marker는 Edge가 제거하고 공개 version만 알린다.
4. **수동 정지:** 방장만 HINT/DISCUSS를 PAUSED_HOST로 바꾸며 원래 단계·cursor·남은 밀리초를 보존한다. 재개는 서버에서 새 기한을 계산한다. 단절 자동 정지는 M6에 남긴다.
5. **호환·rollback:** 기존 M2 RPC는 private으로 옮겨 호출해 중복을 줄인다. 활성 판이 있으면 M3 rollback을 거부하고 취소 후 M2 함수/스키마를 복원한다.

# 설계 결정 — M4 (2026-10-28)

1. **표 비밀:** votes는 private+RLS+직접 접근 권한 회수. DTO는 내 제출 여부·전체 제출 수와 종료된 회차 집계만 반환한다. 방장도 개인 표 연결을 조회할 수 없고 Broadcast는 기존 room_id/version만 유지한다.
2. **서버 단일 집계:** 방 잠금, 판/회차/version 검증 후 고유 키로 1인 1표. 전원 제출 때만 집계·재투표/최다 득표/무승부 전환을 동일 트랜잭션으로 수행한다.
3. **동시 투표:** version 충돌은 같은 판·단계·회차에서 아직 미제출일 때만 새 ID로 1회 재시도. 네트워크 실패는 원본 ID를 유지한다. 다른 회차에 과거 의도를 재사용하지 않는다.
4. **M4 종료 경계:** 비동률은 REVEAL_VOTE에서 M5 대기. 재동률은 FINAL_RESULT/DRAW로 안전 종료하고 승점 없이 방장 대기실 복귀를 제공한다. 역할/정답 공개와 정식 승점 확정은 M5에서 연결한다.

# 설계 결정 — 15명·라이어 2명 및 M5 (2026-10-28)

1. 사용자 확정: 라이어 2명 모두 탈락해야 시민 승리. 지목 라이어만 한 번 답하고 정답이면 라이어 팀 전체 승리, 오답이면 탈락 후 생존자 추가 토론/투표. 시민 오지목도 라이어 팀 승리. 2명은 5인 이상 권장하되 선택은 3인부터 허용한다.
2. 역할 배정은 고정 config의 liar_count와 정확히 일치하도록 지연 검사. 기존 1명 unique index를 config 기반 검사로 대체하고 인원 15/힌트 45 경계를 확장한다.
3. 투표 cycle_no로 최초/후속 투표를 분리한다. 탈락자에게는 관전만 허용하며 새 회차에서 표/후보에 포함하지 않는다. 이전 회차의 미확정 요청을 다음 회차에 재사용하지 않는다.
4. 역할 순차 공개 3초·이의 제기 20초·판정 투표 30초는 DB 서버 기한. 기존 인증 snapshot/heartbeat 경로로 전환하며 정답 원문/전체 라이어는 최종 결과 전 공개하지 않는다.
5. NFC·공백·대소문자·검수 동의어만 자동 판정. 시민 전체 과반 찬성만 정답 인정하며 기권은 표로 더하지 않고 전체 시민 분모는 유지한다. 과반 확정/전원 제출/기한 도달 시 결정한다.
6. round_results 유일 키로 팀 승점을 단 한 번 반영한다. 먼저 탈락한 라이어도 팀 승리 시 승점. 취소/무승부는 승점 없음. rollback은 이미 확정한 승점을 취소하지 않는다.
7. 원격 변경 도구의 요청 상태 만료는 공식 SQL Editor로 우회하고, migration과 이력을 같은 트랜잭션으로 적용했다. M5의 원격·데스크톱 결과는 `M5_VALIDATION.md` 참조.

# 설계 결정 — M6 (2026-10-28)

1. 기존 10초 heartbeat·30초 무응답 기준을 유지한다. Presence는 무작위 키와 빈 payload만 게시하고 재조회 신호로 사용한다. 공개 Presence의 위조된 leave/identity로 다른 사람을 탈락·정지시킬 수 없다. 따라서 실제 네트워크 손실과 서버의 끊김 확정 사이에는 최대 약 30초 및 조회/예약 작업 지연이 있다.
2. 끊김 확정 시 30초 복귀 유예. 살아 있는 원래 참가자만 필수이며 대기자·탈락 관전자의 끊김은 판을 멈추지 않는다. 모든 필수 참가자가 돌아오면 자동 복귀한다. 수동 정지는 별도 필드를 유지해 네트워크 복구가 수동 정지를 해제하지 않는다.
3. COLLECT_WORDS부터 이의 제기까지 원래 단계·남은 시간을 보관한다. 역할 공개 전 단어 수집이 정지돼도 역할과 단어를 숨긴다. M5 판정 기한도 복귀 때 재계산하며 기존 표/추측은 유지한다.
4. 방장 heartbeat 만료(30초) 후 추가 30초가 지나면 연결된 원래 생존 참가자 중 입장 순서가 빠른 사람에게 위임한다. 대기실에서는 연결된 유효 참가자 중 고른다. 원래 방장이 복귀해도 권한을 돌려주지 않는다. 유예 후 방장만 30초 추가 대기 또는 승점 없는 판 취소를 선택한다.
5. 인증된 snapshot/heartbeat와 5초 주기 DB 작업이 같은 잠금·전환 함수를 호출한다. 새 끊김/위임을 발견한 게임 명령은 오류 메타데이터를 반환해 전환을 커밋한 후 Edge가 409와 버전 알림을 전송한다. 예외로 전환까지 롤백하지 않는다. 명령 재생은 기존 receipt로 한 번만 반영한다.
6. 미활동 2시간은 사용자 조작/입장/복구만 연장한다. heartbeat·조회·자동 타이머·자동 위임은 연장하지 않는다. 닫힘/만료는 먼저 접근을 막고, 같은 DB 작업이 방·세션·판·비밀·표·결과를 cascade 삭제한다. 사용자가 기존 종료/만료 방 13개와 향후 자동 정리를 명시적으로 승인했다. 백업은 별도 정책이며 schema rollback은 삭제 기록을 복원하지 않는다.
7. 다른 기기 복구는 방→참가자 순서로 잠그고 자격·복구 코드를 회전한다. 이전 코드/토큰은 즉시 거부하며, 복구가 판을 재개했다면 비밀 없는 버전 알림을 전송한다. 브라우저 복구는 기존 로컬 저장 세션과 heartbeat를 재사용한다.
