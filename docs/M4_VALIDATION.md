# M4 검증 — 2026-10-28

## 구현
- 비밀 표 `app_private.votes`: 판·회차·투표자 고유 키, 자기 투표 금지 CHECK, 투표자/대상 모두 같은 판 참가자 FK. RLS 및 anon/authenticated/service_role 직접 읽기 차단.
- 투표 대상 선택→이름 확인→확정. 제출 후 수정/취소 불가. 방장도 참가자와 같은 한 표. 중간 입장자는 투표 불가.
- 전원 제출 시 방 잠금 안에서 한 번 집계. 공개 DTO는 내 제출 여부·전체 제출 인원·종료된 회차의 득표수만 제공하고 voter_id→target_id 연결은 제공하지 않는다. 진행 중인 회차의 득표수도 숨긴다.
- 1차 동률은 공동 1위 후보만 재투표 대상으로, 전체 판 참가자가 다시 투표. 본인 제외. 재동률은 DRAW/FINAL_RESULT와 ended_at을 원자적으로 기록하며 승점 없음. 방장 대기실 복귀 후 새 판 가능.
- 비동률은 REVEAL_VOTE에서 최다 득표자와 집계 표시. 역할 공개·정답 도전·유효 승패/승점은 M5 연결 전 안내만 제공한다.
- 동시 제출의 version 충돌은 같은 판/단계/회차이며 아직 미제출인 경우만 클라이언트가 새 요청 ID로 1회 재시도한다. 응답 유실은 원래 request_id 그대로 재시도하며 서버 receipt로 중복 반영을 막는다.

## 반영과 제한
- 개발 migration `20261028055003_m4_voting`, game-command v4 적용. 기존 함수는 private에 보관해 rollback 가능. 실제 rollback은 활성 판 취소·무승부 결과 대기실 복귀 후 관리자만 실행(표 삭제 포함).
- advisor WARN/ERROR 없음. 보안 INFO 11개는 의도된 private RLS deny-all, 성능 INFO 1개는 기존 미사용 인덱스.
- 연결 끊긴 참가자를 자동 기권시키지 않는다. 전원 복귀·투표를 기다리거나 방장이 판 취소한다. 자동 단절 처리·위임은 M6.
- 재투표 후보가 두 명 이상이면 각 참가자에게 최소 한 명의 합법 대상이 생긴다. 서버는 성립 불가능한 후보 집합도 방어적으로 검사해 무승부 처리한다.
- 모바일 실기기 인수는 미실행. M3의 모바일 확인과 사용자 기존 보류 두 건 유지. M5/마피아 구현은 포함하지 않는다.

## 브라우저 확인
- 내장 브라우저 방장 UI + 일회성 API 참가자 2명으로 게임 시작→힌트→토론→1차 투표. 이름 선택 후 확인 문구→투표 확정, 전원 1표 동률 재투표, 재동률 무승부·1/2차 득표수·승점 없음 표시, 방장 대기실 복귀까지 확인했다. 새로고침 없이 전환됐다.
- 이 확인은 데스크톱 UI와 실제 개발 Edge/DB/Realtime을 사용한 것이며 휴대폰 3대 인수를 대체하지 않는다. 원격/API 방 3개와 UI 방 1개를 종료·정리했다.

- 후속 점검: 무승부 후 기존 참가자들이 나가고 대기자가 방장으로 승계해도 대기실로 복귀할 수 있게 버튼을 참가 여부와 분리했다. 해당 서버 권한/복귀 회귀 테스트 추가 통과.
