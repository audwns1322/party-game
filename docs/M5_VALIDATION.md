# M5 및 15명·라이어 2명 검증 — 2026-10-28

## 상태
코드·로컬 검증 완료, 실제 Supabase 적용/Edge 배포·원격/브라우저 인수는 미완료. DB 변경 도구가 SQL 실행 전에 `Invalid or expired requestState`를 반복 반환했다. 기존 공개 사이트는 M4(최대 12명·라이어 1명) 상태이며 이번 변경이 배포됐다고 간주하지 않는다.

## 사용자 확정 규칙
- 최대 15명, 방장 라이어 1·2명 선택. 기본값 1명, 2명은 5명 이상 권장. 테마/단어 모드와 함께 시작 시 고정.
- 2명인 판은 두 라이어 모두 탈락해야 시민 팀 승리. 지목된 라이어만 정답 도전 1회. 정답 인정이면 라이어 팀 전체 승리, 오답 확정이면 해당 라이어 탈락 후 생존자 추가 토론·투표.
- 시민을 지목하면 라이어 팀 즉시 승리. 탈락 라이어도 라이어 팀이 이기면 같은 팀으로 1승. 직접 입력 후보 선정은 두 라이어의 제출물을 모두 제외한다.

## 구현
- 정원 15명·배정/순서/45턴 제약을 서버와 UI에서 일치시킴. 지연 배정 검사로 config의 정확한 1·2명 보장.
- 투표 집계→3초 역할 공개→3초 후 정답 도전 또는 최종 결과. 서버 기한을 인증 snapshot/heartbeat가 확정하고 클라이언트는 표시와 재조회만 수행.
- 답변 NFC·양끝/연속 공백·대소문자 정규화, 검수한 단어별 동의어. 자동 AI 판정 없음.
- 20초 시민 이의 제기 기간, 제기 시 30초 시민 비밀 판정 투표. 시민 전체 과반 찬성만 정답 인정, 동수/미제출로 과반 미달이면 불인정. 과반 확정·전원 제출·기한 도달 시 서버 확정.
- 탈락자 투표/후보 제외, cycle_no로 후속 회차 분리. 이전 회차 요청이 새 회차로 재시도되지 않도록 클라이언트도 검사.
- 정답/전체 라이어 목록은 FINAL_RESULT에서만 공개. 이전 단계는 제출 답·잠정 판정과 지목된 사람의 역할만 공개.
- round_results 판별 유일 키로 승점 단 한 번 반영, 무승부·취소는 점수 없음. 대기실 복귀와 같은 방 다시 하기, 방 전적 표시.

## 로컬 검증

- NFC/공백/영문 대소문자/동의어, 비지목자 추측 거부, 한 번 제출/receipt 재생·변조 거부.
