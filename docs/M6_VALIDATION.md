# M6 연결 장애·방장 위임·정리 검증 — 2026-10-28

## 구현 및 적용
- 10초 heartbeat, 30초 무응답 확정 후 30초 복귀 유예. Presence는 빈 payload의 재조회 신호이며 판정 권한은 서버에만 있다. 전원 복귀 시 원래 단계/남은 시간으로 자동 복귀한다.
- 수동 정지와 네트워크 정지를 분리하고, 단어 수집 중 정지해도 역할을 비공개로 유지한다. 기다림/취소는 유예 후 방장만 허용하며 기다림도 요청 ID로 한 번만 반영한다. 취소는 승점 없음.
- 원래 생존 참가자만 필수. 기다리는 신규 참가자는 대기실만 보며, 대기자·탈락 관전자는 진행/위임 후보에서 제외한다. 방장 위임은 유효 참가자의 입장 순서, 원래 방장 복귀 시 권한 반환 없음.
- 복구는 방→참가자 잠금 순서, 토큰/복구 코드 회전, 재개 시 버전 알림. 이전 토큰/코드는 즉시 서버 거부.
- 사용자 명령/입장/복구만 2시간 미활동 기한을 연장한다. 조회·heartbeat·자동 전환/위임은 연장하지 않는다. 닫힌/만료 방은 먼저 접근 차단, 예약 작업이 cascade 삭제한다.
- 개발 프로젝트 `wmgpshtqqsqwgyigxcwl`, migration `20261028091227_m6_resilience`, game-command v6·player-recover v4 적용. 도구의 요청 상태 만료 때문에 공식 SQL Editor로 migration+이력을 한 트랜잭션에서 적용했다.
- 사용자 승인 후 기존 종료/만료 방 13개 삭제, pg_cron `party-game-maintenance` 5초 간격 활성화. 실제 성공 실행과 실패 0개 확인. PGlite는 pg_cron 확장을 지원하지 않아 동일 유지관리 함수를 직접 호출한다. 원격에서는 반드시 Cron 설치/active/run 이력을 함께 확인한다.

- 단위 26 + SQL/실제 Edge 핸들러 112 = 138개 통과. build·lint·7개 Edge 타입 통과.
- 임시 지연/확정 끊김 구분, 토론 남은 시간, 직접 수집 역할 비공개, 역할 확인·힌트·투표/재투표·순차 공개·도전·이의 제기 단계 복귀, 수동 정지 유지.
- 다중 끊김 전원 복귀, 방장 단 한 번 위임/복귀, 대기자/탈락자 제외, 전원 부재 시 대기자 위임 금지, 유예 전 취소/대기 거부, 유예 후 방장만 대기·취소, 대기 멱등 재생, 점수 없는 취소.

- SSR UI 검사: 유예 중 진행/취소 제한, 유예 후 현재 방장만 선택, 비밀 단어 기본 숨김, 중간 입장자의 진행 화면/조작 차단. Presence 빈 payload·새로고침 신호 검사.

## 실제 원격 검증
- `M6_REMOTE_PROJECT=wmgpshtqqsqwgyigxcwl node tests/integration/m6-remote.mjs`: 14개 통과.
- 실제 3명 heartbeat → 5분 토론 → 한 명 heartbeat 중단 → 실제 무응답 감지/일시정지/잔여시간 보존 → 복귀 자동 재개.
- 신규 참가자 이번 판 제외, 방장 heartbeat 중단 → 실제 확정 및 30초 유예 → 다음 유효 참가자에게 위임 → 멱등 추가 기다림 → 다른 기기 복구 → 원래 방장 복귀해도 위임 유지.
- 이전 토큰·복구 코드 재사용 거부, 이전 방장의 진행 권한 거부, 취소 전 승점 0, 종료 직후 거부 및 5초 예약 작업 후 실제 삭제 확인, 삭제 후 복구 불가. Broadcast는 room_id/version만.
- 원격 검증 UUID 원장의 방 잔여 0개를 DB에서도 확인했다. 원장은 UUID만 저장하며 비밀 자격은 프로세스 메모리에만 보관한다.
- 데스크톱 최신 UI를 실제 개발 DB에 연결해 3명 판 진행→동반 참가자 heartbeat 중단→끊김 안내/124초 토론 시간 보관→유예 후 30초 더 기다리기→heartbeat 복귀→토론 자동 재개를 확인했다. 새로고침 없이 갱신됐고 추가 기다림 receipt 1개를 DB에서 확인했다. 화면/원격 검증 방 2개 모두 종료 후 예약 삭제됐으며 잔여 0개다.
- 삭제 후에는 참가 세션도 없어 403을 받을 수 있다. 이를 강퇴로 단정하지 않도록 접근 불가 안내 문구를 보완했다. 실제 방 삭제 여부는 원격 상태 검사와 DB 잔여 수로 별도 확인했다.
- 보안 Advisor는 기존 private RLS 무정책 INFO 16개만 반환했다. raw 테이블 직접 조회를 막고 검증된 RPC만 제공하는 의도된 구조다. [안내](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy).

## 남은 검증/운영 한계
- 물리 기기 간 전환·iOS/Android 절전·비행기 모드 인수는 미실행이다. 실제 서버 복구 자격 회전은 원격 검사로 확인했다.
- 네트워크 손실 즉시를 보장하지 않는다. 30초 무응답 확정과 최대 수초의 예약/조회 지연 후 정지한다. 복귀 유예 30초는 확정 기준이다. Presence만으로 서버 신원을 주장할 수 없다.
- 예약 작업 장애 중에도 닫힘/만료 접근은 거부된다. 장애 복구 후 삭제한다. 삭제 목표는 정상 Cron 실행 기준이며 백업 데이터의 즉시 삭제를 뜻하지 않는다.
- rollback은 `supabase/rollback/m6.sql`부터 실행한다. 활성 판이 있으면 거부하며 이미 삭제한 데이터는 복원하지 않는다. 다른 Cron 작업/확장은 제거하지 않는다.
- M7 운영 QA와 마피아는 이 변경에 포함하지 않는다. Cron 실행 로그 보존 운영은 M7에서 점검한다.
