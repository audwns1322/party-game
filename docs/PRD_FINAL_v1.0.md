# 파티 게임 플랫폼 — 최종 PRD v1.0

> 상태: Codex 개발 착수용 기준 명세 / 2026-10-21  
> 결정 출처: Q1~Q45 사용자 답변(라이어 2명 관련 선택은 폐기) + 세부 구현에 대한 설계 권장안  
> 우선순위: **P0를 충족하는 안정적인 라이어 게임 1종 출시**. 기타 파티 게임은 플랫폼 확장 가능성만 확보.

## 0. 결정 및 변경 이력

- **Q41=A:** 첫 출시에는 라이어 게임 하나만 구현. 별도 게임 종류는 만들지 않는다.
- **Q42=B:** 라이어 추측은 자동 판정 후 이의 제기 시 일반 참가자 다수결로 확정한다.
- **Q43=A:** React + TypeScript + Vite + Supabase + Vercel 사용.
- **Q44=B:** 게임 중 연결 끊김 시 즉시 자동 일시정지하여 30초 복귀 유예를 두고, 미복귀 시 방장이 추가 대기 또는 현재 판 취소를 선택한다.
- **Q45=A:** 이전 판 결과·승리 횟수는 현재 방에만 남고, 방 종료/만료 시 삭제한다. 계정·영구 전적 없음.
- Q12, Q17, Q18, Q23, Q24 및 라이어 2명 전용 설계는 사용자 변경 요청에 따라 무효. **라이어는 항상 1명**.
- 별도 승인 없이 추가한 수치/상세 절차는 이 문서에서 **[권장 기본값]**으로 표기. Codex는 임의로 이를 바꾸지 않는다.

## 1. 제품 정의

동일한 장소에 모인 3~12명이 각자의 스마트폰으로 접속하고, 얼굴을 보며 힌트와 토론을 주고받는 실시간 파티 게임 웹앱. 가입/설치 없이 방을 만들고 QR·6자리 방 코드·초대 링크로 입장한다. 게임 운영은 앱이 자동화하되 방장에게 한정된 복구 권한을 준다.

### 성공 조건

1. 서로 다른 기기 3~12대에서 같은 방의 한 판을 종료까지 수행.
2. 비밀 역할·정답·투표 내용이 허가받지 않은 참가자·대기자·방장에게 노출되지 않음.
3. 중복 클릭/재연결/동시 요청으로 투표·승패·전적이 중복 반영되지 않음.
4. 연결 끊김/방장 변경 및 재접속 이후 서버 상태에 일관되게 합류.
5. 방 종료 시 방별 기록과 복구 권한 제거.

### 범위 밖

라이어 2명, 다른 게임의 실제 구현, 가입 및 장기 전적, 공개 매칭, 음성/영상 통신, 결제/광고, AI 의미 판정, 타인 화면의 비밀 정보 관전.

## 2. 플레이 규칙

| 속성 | 결정 |
|---|---|
| 게임 인원 | 3~12명, 시작 시 참여자 고정 |
| 라이어 | 서버가 무작위 1명 선정, 방장도 대상 |
| 제시어 | 내장 단어 / 참가자 직접 입력 |
| 힌트 | 1·2·3바퀴, 서버가 무작위 순서 선정; 발언자 `완료` 후 다음 순서 |
| 토론 | 방장 설정 1·2·3·5분 또는 무제한 |
| 투표 | 각 참가자 1표, 본인 제외, 비밀 제출, 취소·변경 불가 |
| 결과 | 최다 득표자 지목 → 라이어 여부 공개 → 라이어 지목 시 추측 1회 → 승패 |
| 동률 | 공동 1위 후보끼리 1회 재투표, 또 동률이면 무승부 |
| 전적 | 유효한 판의 시민/라이어 팀 승리만 해당 방의 참가자 승수로 집계; 무승부 미집계 [권장 기본값] |

### 2.1 직접 입력 제시어 모드

1. 서버는 먼저 라이어를 비공개로 선정한다.
2. 이번 판의 전체 참가자가 본인 스마트폰에서 비밀 후보를 1개씩 제출한다. 모든 제출물이 다른 참가자에게 노출되지 않는다. [권장 기본값: 공백 제외 2~30자, 제어문자·공백만 입력 금지]
3. 서버는 **시민이 제출한 후보에서만** 단어를 무작위 선정한다. 라이어가 제출한 후보는 배제한다.
4. 제출이 누락된 경우 다음 단계로 진행하지 않으며, 방장은 재제출 요청 또는 판 취소 가능. 단어 제출 도중 퇴장 시 중단/복구 정책을 따른다.
5. 선정된 제시어는 시민에게만 보여주고 라이어에게는 공개하지 않는다. 공통 카테고리는 사용자 지정 모드에서 '직접 입력' 등 일반 표시만 제공한다.
6. 일반 참가자가 자신이 낸 단어가 뽑힐 가능성은 MVP에서 수용한다(확률적 문제이지 보안 취약점은 아님).

### 2.2 힌트와 토론

- 역할 정보는 기본적으로 가리고 **길게 눌러 확인**한다. 터치 종료·화면 이탈 시 즉시 숨긴다. 기기 자체 캡처까지 방지한다고 주장하지 않는다.
- 순서는 서버에서 생성해 방 전체에 공유한다. 발언자만 `완료` 명령을 보낼 수 있고, 요청 시 해당 발언 순서 및 버전을 검증한다.
- 모든 바퀴 완료 후 토론 시작. 토론 기한은 서버 타임스탬프 기준으로 계산; 무제한 선택 시 방장이 `투표 시작` 버튼으로 다음 단계로 넘긴다. 제한 시간이 남아 있어도 방장은 확인 버튼을 한 번 더 눌러 토론을 조기 종료할 수 있다(2026-10-24 사용자 요청).
- 기한 도달로 인한 자동 단계 이동은 서버 스케줄/요청 시 검증 중 최소 하나를 통해 권한 검증과 함께 보장한다. **클라이언트 타이머만으로 진행하지 않는다.**

### 2.3 투표와 동률

- 투표 대상: 이번 판의 참가자 전체 중 자기 자신 제외. 동률 재투표 때는 공동 1위 후보들 중 자기 자신 제외.
- 모든 **활성 판 참가자**의 유효 투표가 제출되면 자동 집계. 연결 끊긴 참가자도 복귀 후 투표해야 하며 임의 기권 처리하지 않는다.
- 동률 재투표 후보 중 본인만 남아 투표 가능 대상이 없는 등 성립 불가능한 경우는 즉시 무승부로 안전 종료한다. [권장 예외]
- 재투표에서 또 공동 1위면 무승부. 개별 투표의 `voter_id → target_id` 연결은 공개하지 않는다. 공개 가능한 것은 단계 종료 후 후보별 **집계 득표수**뿐.
- 무승부는 실제 라이어 및 단어를 결과 단계에서 공개하지만 어떤 팀에도 승점을 주지 않는다.

### 2.4 정답 도전 및 이의 제기

- 라이어가 지목된 경우에만 정답 도전 화면 등장. 라이어는 텍스트를 **한 번** 제출하며 수정 불가.
- 서버 자동 판정: Unicode NFC 정규화, 양끝 공백 제거, 연속 공백 정리, 한글·영문 대소문자 처리, 미리 승인된 단어별 동의어 비교. 임의의 LLM 호출/유사도 판정은 하지 않는다.
- 앱은 답변과 잠정 판정(정답/오답)을 보여주되, **정답 제시어 자체는 최종 판정 전까지 라이어에게 노출하지 않는다.**
- **[권장 기본값] 이의 제기 20초:** 일반 참가자 중 한 명이 제기 가능. 기간 내 제기 없으면 잠정 판정 확정.
- 이의 제기 발생 시 **해당 판 시민 전원**에게 찬성(정답 인정)/반대(오답) 비밀 투표를 표시한다. 절반을 초과하는 찬성일 때 정답 인정. 동수·그 미만이면 오답. **[권장 기본값] 30초 투표 기한**; 기한까지 미제출은 반대로 계산하지 않고, 과반은 원래 시민 전체 인원 기준. 즉 미제출이 과반 확보를 방해할 수 있다.
- 판정 투표 진행 중 연결 끊김은 Q44 일시정지 정책 적용. 게임 종료/취소 시 승점 갱신 없음.
- 이의 제기 판정자는 라이어 제외, **방장인 시민도 1표**. 방장이라고 정답을 임의로 판정할 수 없음.
- 시민이 아닌 사람을 지목했다면 라이어가 즉시 승리한다.
- 최종 판정 확정 후 서버 트랜잭션에서 결과와 승점을 단 한 번 기록한다.

## 3. 룸 라이프사이클

### 3.1 방 생성·입장·정원

- 시작 화면: `방 만들기`, `참가하기`를 최상위 행동으로 표시. 공통 다크 테마, 라이어 게임 개별 테마.
- 익명 닉네임 사용. **[권장 기본값] 2~16자, 방 내 활성 닉네임 중복 불허**. 부적절 내용 필터는 향후 보강 가능.
- 방 코드: 숫자 6자리, 활성 방끼리 고유. 임의 생성·충돌 재시도. **코드는 인증 수단이 아니라 입장 경로**이므로 방장 명령 및 정보 조회는 세션 자격으로 검증.
- 방 내 현재 판 참여자는 3~12명. **[권장 기본값] 입장 대기자를 포함해 방 전체 12명 상한**. 게임 중 대기자 추가는 정원 안에서만 허용. 현재 판에는 끼어들 수 없음.
- 방장도 실제 참가자로 플레이. 방장의 제어 권한은 시작·재시작·일시정지·안전한 단계 건너뛰기·판 취소·방 종료에 제한. 역할/투표 비밀 열람 권한 없음.
- 게임 시작 시 `round_players`를 스냅샷으로 확정, 새 참가자는 `waiting_next_round` 상태. 다음 판 시작 시 대기자를 포함하되 3명 미만이면 시작 불가.

### 3.2 식별·재접속

- 참가 세션은 임의 추측 불가능한 원시 토큰으로 식별하고 **DB에는 토큰 해시만 저장**. 클라이언트에 Supabase service_role 및 서버 비밀 키를 제공하지 않는다.
- 같은 브라우저에서는 보관된 개인 토큰으로 조용히 복구. 다른 기기에서는 사용자에게만 보여준 개인 복구 코드를 입력해 복구하고 **기존 자격 증명을 회전**시킨다.
- 복구 성공 시 이전 접속 세션 폐기 또는 교체. 여러 기기가 동시에 같은 참가자로 투표할 수 없게 서버에서 검증.
- 복구 코드 최소 128비트 무작위성 또는 이에 준하는 보안 수준. 단순 짧은 숫자 6자리는 복구 코드로 사용하지 않는다.
- 인증 유무와 상관없이 비밀 데이터는 라운드별 소유자 기준으로 조회 제한.

### 3.3 연결 끊김 — Q44=B 상세 명세

1. **게임 진행 중** 현재 판 참가자의 연결 끊김을 서버가 확인하면 해당 판을 `PAUSED_DISCONNECT`로 원자적으로 전환하고 모든 진행 타이머를 정지/잔여시간 저장한다. 임시 무선망 흔들림 대비 **[권장 기본값] 3초 디바운스** 허용; 그 사이 복구 시 사용자에게 일시정지를 노출하지 않아도 된다.
2. **[권장 기본값] 30초 복귀 유예** 카운트다운. 복귀 시 모든 필수 참가자가 다시 연결되어 있으면 기존 단계·남은 시간으로 자동 재개한다.
3. 유예시간 내 미복귀면 **방장에게 '계속 기다리기' 또는 '현재 판 취소'** 버튼 제공. 기다리기를 선택하면 정지 상태 유지; 취소는 결과·승점 없이 대기실 복귀. 방 종료와 판 취소는 다른 행동이다.
4. 복귀 후 방장은 재개를 명시적으로 누를 수도 있으나, 참가자 전원 복귀 시 자동 재개가 기본. 끊김이 여러 명이면 모두 복귀 필요.
5. **방장 연결 끊김**도 같은 중단 정책이 적용되며 30초 후 연결된 판 참가자 중 입장 순서가 빠른 자에게 방장 권한 자동 위임. 기존 방장이 복귀해도 권한을 자동 반환하지 않는다. 새 방장이 이후 대기/취소를 결정한다.
6. 입장 대기자(현재 판 비참가자)의 끊김은 판을 중단하지 않는다.
7. 무제한 대기로 장기간 방이 방치될 경우 방의 미활동 만료 정책이 우선 적용된다.
8. 서버의 연결 판정은 Realtime Presence 신호와 마지막 heartbeat를 조합하고, 짧은 지연을 고려한다. 모든 결정은 DB 권위 상태로 확정한다.

### 3.4 방 종료·기록 — Q45=A 상세 명세

- 방장은 명시적으로 방을 종료할 수 있다. **[권장 기본값] 최근 2시간 동안 사용자/게임 명령이 없으면 자동 만료**.
- 방 운영 중에는 `round_results`와 승리 횟수 보관. **방 종료·만료 시 방, 참가 세션, 후보 단어, 역할, 투표, 결과, 승리 횟수를 삭제**한다(개발/운영 로그는 비밀·닉네임 등 개인정보가 포함되지 않도록 별도 최소화).
- 서버 주기 작업으로 만료된 방 및 하위 데이터를 삭제한다. **[권장 기본값] 만료 후 5분 이내 삭제 작업 실행 목표**. 삭제 전에도 `closed` / `expired` 상태의 조회·명령은 즉시 거부한다.
- 데이터베이스 백업의 일반 보존 정책과 서비스 운영 로그까지 즉시 삭제되는 것으로 오해하지 않도록 서비스 안내에 명시한다. 백업 보존·폐기는 인프라 정책 검증 후 공개.
- 영구 개인 식별이나 방 재생성 시 전적 연결은 제공하지 않는다.

## 4. 권위 상태 머신 (Codex 필수)

### 4.1 단계 정의

`LOBBY → ASSIGNING → (COLLECT_WORDS | REVEAL_ROLE) → REVEAL_ROLE → HINT → DISCUSS → VOTE_1 → (VOTE_RUNOFF | REVEAL_VOTE) → REVEAL_VOTE → REVEAL_LIAR → (GUESS | FINAL_RESULT) → (APPEAL_WINDOW | FINAL_RESULT) → (APPEAL_VOTE | FINAL_RESULT) → FINAL_RESULT → LOBBY`

- 직접 입력이면 `ASSIGNING → COLLECT_WORDS → REVEAL_ROLE`; 기본 단어면 `ASSIGNING → REVEAL_ROLE`.
- `VOTE_1` 집계 동률 → `VOTE_RUNOFF`, 비동률 → `REVEAL_VOTE`.
- `VOTE_RUNOFF` 재동률이면 내부 결과 `DRAW` 설정 → `REVEAL_VOTE → FINAL_RESULT`.
- `REVEAL_LIAR`에서 지목자 ≠ 라이어면 `FINAL_RESULT`; 맞으면 `GUESS`.
- `GUESS` 제출 → 자동 잠정 판정 → `APPEAL_WINDOW`; 미제기 종료 → `FINAL_RESULT`, 제기 → `APPEAL_VOTE` → `FINAL_RESULT`.
- 공개 화면 전환(`REVEAL_VOTE`, `REVEAL_LIAR`, `FINAL_RESULT`)은 **[권장 기본값] 각 3~5초 자동 전환**; 사용자 기기에서 건너뛰어도 서버 단계는 그대로 유지.
- 비정상 상황은 `PAUSED_DISCONNECT`, `PAUSED_HOST`, `CANCELLED`로 모델링하고 **일시정지 직전 단계 및 남은 시간**을 별도 저장. `CANCELLED`는 승점 없이 LOBBY로 이동한다.

### 4.2 상태 전이 규칙

- 모든 상태 변경은 **서버 명령 하나 = DB 트랜잭션 하나**로 처리. 기존 `round.version`과 요청 `request_id`를 검증하고, 정확히 하나의 유효한 전이만 허용한다.
- `started_at`, `deadline_at`, `paused_at`, `remaining_ms`, `phase`, `phase_version` 서버 관리.
- 현재 단계의 소유자(예: 발언 중인 사람) 또는 방장 관리 권한이 없는 명령은 거부한다.
- 동시 요청은 DB 잠금/조건부 갱신으로 직렬화. 프런트 상태는 서버 조회 및 실시간 이벤트로만 갱신.
- 클라이언트는 `expected_phase`, `expected_version`, `request_id`를 전송하며, 오류 응답은 재조회할 수 있는 안전한 메시지를 제공한다.
- 단계마다 한 번만 실행되는 부작용(무작위 배정, 집계, 점수)은 DB 유니크 키와 상태 검사로 중복 실행 차단.

### 4.3 주요 명령

| 명령 | 허용 주체 | 조건/효과 |
|---|---|---|
| `create_room`, `join_room` | 익명 신규 | 정원·코드 확인, 자격 발급 |

## 6. 기술 아키텍처 — Q43=A

```
스마트폰 브라우저 (React / TypeScript / Vite)
  ├─ 공개 화면: Supabase Realtime Broadcast/Presence (비밀 payload 금지)
  ├─ 개인 상태: 인증된 서버 함수 호출 → 소유자 검증 → 개인 DTO
  └─ 게임 명령: 서버 권한 API (Supabase Edge Functions)
                                   ↓
                Postgres 트랜잭션 / 제한된 SQL RPC
                  ├─ 방·세션·단계·타이머
                  ├─ 비밀 역할·단어·표 (직접 테이블 구독 금지)
                  └─ 집계/결과/방 내 전적

Vercel: 정적 프런트 호스팅
Supabase: DB / Auth 대체용 익명 세션 검증 레이어 / Realtime / Edge Functions
```

- 로그인 없는 **사용자 정의 익명 참가자 토큰**을 사용한다. RLS를 우회하는 `anon` 공용 직접 쓰기 권한을 열지 않는다.
- 일반 클라이언트가 `service_role` 키나 DB 비밀 테이블을 직접 접근하지 못하게 한다. 쓰기는 검증된 Edge Function에서만 처리; 읽기도 안전한 참가자별 DTO API 사용.
- Edge Function에서 서버 전용 비밀과 참가자 세션을 검증 후 최소 권한 RPC를 실행. 테이블별 `REVOKE` / RLS / SECURITY DEFINER 함수의 `search_path` 설정 등을 확인한다.
- Realtime 공개 이벤트에는 `room_id`, `round_id`, `phase`, `version`, `deadline`, `connected_count`, 공개 득표 총합 등의 비밀이 아닌 내용만 실어 보낸다. 수신자는 새 버전을 보고 자신의 인증된 스냅샷을 재조회한다.
- 프런트 라우트: `/`, `/room/:code`, `/room/:code/play`, `/room/:code/result`. 방 코드만으로 개인정보/비밀 열람 불가.
- 게임 엔진 모듈 경계: `GameDefinition`(ID, 설정 스키마, 플레이 단계, 명령, 공개/개인 DTO)와 `liar` 구현을 구분. 그러나 사용하지 않는 게임의 인터페이스와 추상화는 최소화.
- 현재 라이브러리 버전·Supabase/Vercel 무료 플랜 한도·Realtime 동시 연결 정책은 **Codex 착수 시 공식 문서로 검증**하고 잠금 파일에 고정한다.

| `round_players` | `round_id`, `player_id`, `role`, `acknowledged_at`, `eligible` | 역할 비밀, 서버 전용 |

| `votes` | `round_id`, `ballot_no`, `voter_id`, `target_id`, `unique(round_id,ballot_no,voter_id)` | 비밀, 종료 후 집계만 |

| `round_results` | `round_id unique`, `winner`, `liar_player_id`, `nominated_player_id`, `is_draw`, `finalized_at` | 최종 확정 후 공개 |
| `command_receipts` | `room_id`, `player_id`, `request_id unique`, `response_meta`, `created_at` | 멱등 처리 |

**필수 DB 불변식:** 각 방 진행 중 판 최대 1개; 판당 라이어 정확히 1명; 방장 반드시 해당 방 참가자; 한 판·한 회차·한 명 최대 1표; 판 결과 및 승점 갱신 정확히 1회; 닫힌 방 명령 즉시 차단. 필요한 `CHECK`, `FOREIGN KEY`, `UNIQUE`, `INDEX`, 트랜잭션 검증을 함께 적용.

연결 상태는 Realtime Presence만을 절대 진실로 취급하지 않으며, 마지막 heartbeat와 서버 시간으로 검증. 세션 토큰 원문·제시어·개별 표·복구 코드 원문을 로그에 남기지 않는다.

## 8. API 계약 (권장 표면)

- `POST /functions/v1/room-command`: `{room_id, action, payload, request_id, expected_version}`; 참가자 Bearer 토큰 검증. 허용/거부 및 최신 `version` 반환.
- `GET /functions/v1/room-snapshot?room_id=...`: 참가자 토큰 검증 후 공개 상태와 **본인 허용 정보만** 반환.
- `POST /functions/v1/room-join`: `{room_code, nickname}` → 참가자 자격·복구 코드 발급.
- `POST /functions/v1/player-recover`: `{room_code, recovery_code}` → 기존 자격 회전 및 새 세션.
- `POST /functions/v1/room-create`: `{nickname}` → 방·참가자 자격 발급.

Edge Function URL 및 이름은 실제 배포 명명 규칙에 따라 조정 가능하나 계약과 권한은 유지. 모든 API는 `request_id` 기준 멱등 처리/응답 코드 표준화. 프런트가 제공한 `role`, `winner`, `word`, `vote_count` 등 결정 값은 신뢰하지 않는다.

## 9. 보안·운영·성능

- RLS/권한 회귀 테스트를 자동화. 인증되지 않은 조회, 타인 자격, 역할 위조, 중복 투표/명령, 폐기 자격 및 방 코드 브루트포스 시도를 테스트.
- 방 코드 생성·참가·복구 API에 요청 속도 제한과 오용 방지를 적용. 사칭 방지를 위해 복구 코드를 보호하고 회전.
- 원문 닉네임/후보 단어는 XSS 방지를 위해 텍스트로만 렌더링, HTML로 삽입하지 않는다.
- `VITE_*` 환경변수는 공개되는 값만 사용. DB 키·service_role은 서버 비밀 저장소에만 등록.
- 만료 정리는 스케줄러로 실행하되, 스케줄 실패 시에도 닫힌 방 접근 차단이 선행되어야 한다.
- 대상 브라우저: 최신 iOS Safari, Android Chrome. **[권장 목표]** 12인 방에서 보통 네트워크 환경의 단계 전환 반영 2초 이내(실기기 측정 필요).
- 로그: request_id, 오류코드, 소요시간만 저장; 제시어/투표/복구 키는 기록 금지.

## 10. 인수 기준 (P0 통과 조건)

1. 3명 및 12명 실기기/시뮬레이션 방에서 3판 연속 완료.
2. 방장 라이어 상태에서도 다른 사람의 역할·표·제시어 사전 열람 불가.
3. 익명 방 코드만 가진 외부인은 방 비밀 조회 불가.
4. 내장 단어 및 직접 입력(라이어 단어 제외) 모드 통과.
5. 힌트 1·2·3바퀴 순서, 토론 1·2·3·5분/무제한 동작.
6. 중복/자기 투표 방지, 공동 1위 재투표 1회, 재동률 무승부.
7. 라이어 지목 성공/실패 및 추측 정답/오답 검증.
8. 자동 판정 후 이의 제기: 과반 찬성·부결·미제출·기한 종료 검증.
9. 플레이 중 한 명 연결 끊김: 자동 정지 → 30초 유예 → 방장 기다림/판 취소 → 점수 미반영.
10. 방장 이탈: 30초 후 유효한 다른 참가자에게 자동 위임, 기존 방장 재입장해도 재위임 없음.
11. 브라우저 자동 복귀/다른 기기 복구 코드 회전/이전 세션 차단.
12. 게임 중 신규 입장자는 대기실만 볼 수 있음.
13. 판 결과 중복 수신/명령 재시도에도 전적 1회 반영.
14. 방 종료·만료 후 기록 삭제, 토큰·초대 링크로 조회 및 복구 불가.
15. iOS/Android 작은 화면에서 비밀 보기/투표 카드/확정 UI 동작.
