# 토큰 절약 작업 규칙 v2

## 원리

- Claude는 단계마다 **기본 지침 + 연결된 도구 목록 + 지금까지의 대화 전체**를 다시 읽는다.
- 그래서 토큰을 늘리는 요인은 세 가지다. 연결된 도구 수, 대화 길이, 주고받는 횟수.
- 2026-10-24 party-game 세션에서는 사용량의 약 75%(추정)가 기본 지침과 도구 목록이었다.

> **최우선 원칙:** 토큰을 아끼려고 테스트, 보안 검증, 결과 확인을 생략하지 않는다.
> 줄여야 할 것은 불필요한 반복이지 검증이 아니다.

---

## A. 대화 시작 전 (내가 할 일)

1. **이 작업에 안 쓰는 커넥터는 대화에서 꺼둔다.**

   | 작업 | 켤 것 |
   |---|---|
   | party-game 개발 | Supabase |
   | 배포 | Vercel 추가 |
   | 문서·회의록 | Notion |
   | 그 외 (Chrome, Atlassian, Google Sheets) | 필요할 때만 |

2. **GitHub 저장소는 첫 메시지에서 연결한다.** 중간에 연결하면 세션이 재시작돼 지침을 다시 불러온다.
3. **GitHub 푸시 권한(Claude GitHub App)을 미리 연결해 둔다.** 푸시 실패 후 재시도하는 왕복이 사라진다.
4. **작업 난이도에 맞는 모델을 고른다.**
   - 간단한 수정, 문서 정리, 질문: 가벼운 모델(Sonnet·Haiku)
   - 설계, 보안, 복잡한 디버깅: 상위 모델(Opus)

## B. 대화 단위 관리

5. **대화 하나에는 마일스톤 하나만 담는다.**
   - 같은 마일스톤 안에서는 같은 대화를 이어간다. 새 대화마다 복제, 문서 읽기, 환경 설치를 반복하게 된다.
   - 마일스톤이 끝나면 HANDOFF를 갱신하고 새 대화를 연다. 대화가 길어질수록 매 단계 다시 읽는 양이 커진다.
6. **주제가 다른 질문은 별도 대화에서 한다.** 개발 중에 다른 질문을 섞으면 그 내용도 계속 다시 읽힌다.

## C. 요청할 때

7. **여러 단계를 한 번에 맡긴다.** 예: "M0 검증부터 문서 갱신·커밋까지 한 번에 진행해줘."
8. **판단 기준을 미리 준다.** 예: "되돌릴 수 있는 건 판단해서 진행하고, 되돌릴 수 없는 작업(DB 삭제, 운영 배포, 강제 푸시)만 물어봐."
9. **결과 형태를 먼저 정한다.** 예: "완료/남은 일/결정할 것 3묶음, 10줄 이내."
10. **범위를 지정한다.** 예: "HANDOFF.md 기준으로 시작하고 필요한 파일만 열어봐."
11. **긴 로그와 파일은 붙여넣지 말고 첨부하거나 경로를 알려준다.** 에러는 핵심 몇 줄만 붙인다.
12. **서브에이전트(병렬 작업)는 꼭 필요할 때만 요청한다.** 에이전트마다 지침을 처음부터 다시 읽는다.

## D. Claude의 작업 방식

13. 파일은 필요한 부분만 읽고, 이미 읽은 파일은 다시 읽지 않는다.
14. 명령 출력은 `tail`이나 요약으로 줄이고, 여러 검사는 한 번에 묶어 실행한다.
15. 한 번에 할 수 있는 조회나 명령은 병렬로 묶는다.
16. 결과 보고는 완료, 남은 일, 결정할 것만 쓴다. 과정은 다시 설명하지 않는다.
17. 실패한 작업은 원인을 확인한 뒤 한 번만 재시도한다. 같은 방법으로 반복하지 않는다.

## E. 다음 대화로 넘기는 방법 (HANDOFF)

18. **`docs/HANDOFF.md`는 덧붙이지 말고 최신 상태로 덮어쓴다.** 1화면 분량을 넘기지 않는다. 지난 기록은 git 이력에 남는다.

    ```md
    ## 현재 상태      (마일스톤, 완료 여부)
    ## 다음 작업      (바로 할 일 1~3개)
    ## 차단 요인      (무엇이 막혔고 무엇이 필요한지)
    ## 환경           (Node 버전, 실행 명령, 연결된 서비스)
    ```

19. **환경 준비는 스크립트 하나로 만든다.** 예: `scripts/setup.sh`에 Node 설치, `npm ci`, `.env.local` 생성 안내, git 설정을 넣는다. 새 대화에서는 "setup.sh 실행해줘" 한 줄이면 된다.
20. **비밀 값(키, 비밀번호, 토큰)은 대화나 HANDOFF에 쓰지 않는다.** 공개 키도 `.env.local`에만 둔다.

## F. 점검

21. 마일스톤이 끝날 때 "이번 세션 토큰 사용량 보여줘"로 확인하고, 크게 쓴 부분이 있으면 이 규칙을 고친다.
